# Spec: React/Vite Layout — Header & Footer

**Feature ID**: 003
**Branch**: 3-react-layout
**Status**: Ready for planning
**Created**: 2026-03-17

---

## Overview

When ForgeKit generates a React/Vite frontend, the scaffolded project currently has no global layout. Users must wire up navigation and branding from scratch. This feature adds a reusable `Layout` component (with `Header` and `Footer`) to the generated project so that every route benefits from consistent chrome out of the box.

---

## Problem Statement

Projects generated with the React/Vite option have a bare `App.tsx` with no global navigation, header, or footer. Developers must build these from scratch even though the information needed (project name, auth state) is already available at generation time.

---

## Goals

- Every React/Vite project generated by ForgeKit includes a functional `Layout`, `Header`, and `Footer`.
- The Header displays the project name and adapts to whether auth is enabled.
- The Footer displays copyright and static placeholder links.
- No manual wiring is required — the router already uses the Layout.

---

## Out of Scope

- Custom navigation items beyond the home route (nav links are placeholder stubs).
- Dynamic link configuration via `ProjectConfig`.
- Theming or design customization beyond what Tailwind provides by default.
- Auth logic itself (handled by existing `useAuth` / `ProtectedRoute`).

---

## User Scenarios

### Scenario 1 — Generate without auth

**Given** a developer runs `forgekit new` and selects React/Vite without auth
**When** they open the generated project in a browser
**Then** they see a Header with the project name and navigation, and a Footer with copyright and placeholder links.
**And** there is no login/logout button.

### Scenario 2 — Generate with auth

**Given** a developer runs `forgekit new` and selects React/Vite with auth enabled
**When** they open the generated project
**Then** the Header shows the project name, navigation, and a login/logout button.

### Scenario 3 — All routes share the layout

**Given** any route is added to the router
**When** the user navigates to that route
**Then** the Header and Footer are always visible.

---

## Functional Requirements

### FR-1: Layout component
The generator creates a `Layout` component that renders a `Header`, a `<main>` content area (via `<Outlet />`), and a `Footer`.

### FR-2: Header — project name
The Header displays the project name as defined in `ProjectConfig.projectName`.

### FR-3: Header — navigation
The Header includes a navigation area with at least one placeholder link (Home → `/`).

### FR-4: Header — auth button (conditional)
If auth is enabled in `ProjectConfig`, the Header renders a login/logout button wired to the `useAuth` hook. If auth is disabled, no such button appears.

### FR-5: Footer — copyright
The Footer displays `© {currentYear} {projectName}`.

### FR-6: Footer — static links
The Footer includes three placeholder anchor tags: Docs, GitHub, and Privacy Policy. The href values are `#` (to be replaced by the developer).

### FR-7: Router integration
Both `index.tsx` (no auth) and `index-auth.tsx` (with auth) router templates are updated to wrap routes in a layout route using the `Layout` component via React Router's nested routing.

### FR-8: Generator writes new files
The `react-vite.ts` generator writes `Layout.tsx`, `Header.tsx`, and `Footer.tsx` into `src/components/` of the generated project.

---

## Success Criteria

- A generated project without auth renders a Header and Footer on every page, with no login/logout button visible.
- A generated project with auth renders a login/logout button in the Header on every page.
- Navigating between routes does not unmount the Header or Footer.
- The Footer always shows the current year and the configured project name.
- The Footer contains three non-functional placeholder links labelled Docs, GitHub, and Privacy Policy.
- `npm test` passes after the generator changes with no new test failures.

---

## Key Entities

| Entity | Description |
|---|---|
| `Layout` | Wrapper component: `<Header> + <Outlet> + <Footer>` |
| `Header` | Top bar: project name, nav links, optional auth button |
| `Footer` | Bottom bar: copyright + static links |
| `ProjectConfig.projectName` | String used at generation time for project name |
| `ProjectConfig.auth` | Boolean flag controlling presence of login/logout button |

---

## Assumptions

- The generated project uses Tailwind CSS (already included in the React/Vite template).
- React Router is already present (`react-router` package in the template).
- `useAuth` hook is already generated when auth is enabled — the Header simply imports and calls it.
- The year in the Footer copyright is hardcoded to the generation year (i.e., `new Date().getFullYear()` rendered at generation time, not runtime).

---

## Dependencies

- `src/generators/frontend/react-vite.ts` — must be updated to write 3 new template files.
- `src/templates/frontend/react-vite/src/router/index.tsx.hbs` — updated to use layout route.
- `src/templates/frontend/react-vite/src/router/index-auth.tsx.hbs` — updated to use layout route.
- Existing `useAuth.ts.hbs` hook (when auth enabled).
