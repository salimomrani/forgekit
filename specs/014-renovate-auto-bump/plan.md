# Implementation Plan: Renovate Auto-Bump Pipeline

**Branch**: `014-renovate-auto-bump` | **Date**: 2026-04-16 | **Spec**: [spec.md](./spec.md)

## Summary

Ship a single `renovate.json` at the repo root that (a) auto-bumps `package.json` npm deps with weekly grouped PRs and auto-merge for devDeps minor/patch, and (b) adds custom regex managers to bump the `FALLBACK_VERSIONS` constants in `src/versions.ts` against npm, Maven Central, and Packagist. The Renovate GitHub App is already installed — no secrets, no new GitHub Actions workflow.

## Approach

### 1. Core `renovate.json` skeleton

- Extends `config:recommended`.
- `schedule`: `["before 9am on monday"]`.
- `timezone`: `Europe/Paris` (maintainer tz).
- `labels`: `["dependencies"]`.
- `prConcurrentLimit`: `5` (avoid PR spam).
- `rangeStrategy`: `bump` (update semver range, not pin).
- `packageRules`:
  - Group minor/patch for all managers → single PR titled `chore(deps): update non-major dependencies`.
  - Majors → isolated PRs.
  - devDependencies minor/patch → `automerge: true`, `automergeType: branch`.
  - Production dependencies → `automerge: false`.

### 2. Custom regex manager for `FALLBACK_VERSIONS`

Single `customManagers` entry (customType: `regex`) covering all 36 constants regardless of datasource. Each constant carries an inline marker comment:

```ts
angular: "21.0.0", // renovate: datasource=npm depName=@angular/core
springBoot: "4.0.2", // renovate: datasource=maven depName=org.springframework.boot:spring-boot-starter-parent
laravel: "13.1.1", // renovate: datasource=packagist depName=laravel/framework
```

One regex pattern captures `currentValue`, `datasource`, `depName` via named groups (Renovate uses these verbatim — no `datasourceTemplate` / `depNameTemplate` needed):

```
\w+:\s*"(?<currentValue>[^"]+)",\s*//\s*renovate:\s*datasource=(?<datasource>npm|maven|packagist)\s+depName=(?<depName>[^\s]+)
```

**Distribution by datasource** (36 keys total):
- **npm** (30 keys): `angular`, `angularBuild`, `primeng`, `primeuixThemes`, `primeicons`, `primeflex`, `ngrxSignals`, `rxjs`, `zoneJs`, `typescript`, `tailwind`, `react`, `reactRouter`, `vite`, `axiosReact`, `next`, `nextAuth`, `prismaClient`, `nestjs`, `nestjsJwt`, `nestjsSwagger`, `vue`, `pinia`, `vueRouter`, `husky`, `lintStaged`, `prettier`, `eslint`, `typescriptEslint`, `eslintConfigPrettier`
- **maven** (3 keys): `springBoot`, `springDoc`, `mapstruct`
- **packagist** (3 keys): `laravel`, `sanctum`, `scramble`

**Special case** — `next-auth` tracks the `beta` dist-tag (v5 beta chain). A dedicated `packageRules` entry forces `followTag: "beta"` so Renovate bumps along the beta channel instead of treating npm `latest` (`4.x`) as a downgrade.

Single-manager + marker-comment strategy: self-documenting, O(1) to add a new constant (just add the marker), no `src/versions.ts` refactor risk.

### 3. Validation

Run `npx --package renovate -c 'renovate-config-validator' renovate.json` locally before committing. Expect exit 0.

### 4. Rollout

1. Commit `renovate.json` + marker comments on `src/versions.ts` to branch `014-renovate-auto-bump`.
2. Open PR to `master`.
3. **Verify GitHub branch protection on `master` lists the `ci.yml` jobs as required checks** — without this, Renovate's auto-merge can land unverified changes. This is a repo-settings action, outside the diff.
4. After merge: Renovate App picks up the repo, runs within 1h, opens onboarding PR or first dep update PR.
5. Verify first PR within 7 days.

## Risks & Mitigations

- **Regex mismatch** → test against actual `src/versions.ts` using `renovate --dry-run` locally if time permits (optional).
- **Auto-merge on a broken patch** → CI must be green (existing `ci.yml` gates: lint + unit + e2e + build). Already enforced — no extra risk.
- **`src/versions.ts` refactor breaks regex** → marker comments are explicit; a future refactor that removes them will simply stop Renovate from seeing those constants, never causing false bumps.

## Out of Scope

- Bumping versions inside template files (`*.hbs`) — those use `{{versions.*}}` placeholders resolved at generation time.
- Bumping the ForgeKit package itself (release flow uses `git tag vX.Y.Z`, Principle 9).
- Dependabot parallel configuration.
- Self-hosted Renovate via GitHub Action.
